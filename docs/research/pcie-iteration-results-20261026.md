## 已检验的机制

1. **规划复用。** 24 请求 / 1536 候选与 fresh full forecast 对照相同。三档完整 memo screen 复用了约 4.4k–5.1k 次工作链刷新、各 380 次相同 route。闭环中 44–60 个 PD 对仍发生变化，因为实际规划耗时改变了交错；因此不能假定“同公式就必然同结果”。中档最慢 feal:12 在 D API 内有约 13.76 秒其他请求占用。
2. **年龄排序并非足够。** age screen 实际改变 122/75/135 个 prefill 迭代，但两档只有约 0.8% 改善，低档退化 4%。低档 headless:11 的等待部分减少，自己所在迭代的工作却增大；缓存演化、路由和批成员共同改变，不能只归因年龄。故未选为升级版。
3. **剩余松弛量。** 以 ready + J 为共同 TTFT 截止时间，比较 ready - remaining_first_work，J 和当前时刻消去。只用已完成 chunk 进度与已发出成本，无 task/rate 权重。保留 decode-first、容量 FIFO、H2D/save 和完整释放。动态优先级 crossing 限制预测合并步长，已与逐步回放核对。
4. **资源仲裁失配。** laxity 中档参考 feal:11 从 P 完成到 D API 开始等 54.45 秒。D control 约 0.575 秒后已经完成，之后到 handoff 开始还有 53.875 秒。源 P 后续 API 覆盖其中 53.083 秒，D 同期 busy 43.735 秒（两者重叠，不可相加）。handoff 本身约 0.000803 秒，软件 link wait 为 0。执行循环优先节点编号，而预测按请求次序，足以制造不一致。不能把这部分收益当 RDMA 拥塞改善。
5. **保守修正。** fair screen 两 arm 都沿预测的 request-order 争抢端点资源，完整保留源/目的 gate、方向链路、lease 和容量。它修正 CPU 模型，不是已部署的原生服务修复。也没有假定 host copy 与计算完全免费重叠。
6. **资源顺位。** 单纯重新排序循环，仍可能在两个端点释放时刻错开时，让新的单端计算抢走刚释放的一端。reservation 版对已就绪复制的资源顺位作保留，允许更老的持有者和无关端点进展，阻止更年轻的冲突操作插队。实际联合 acquire 才记为持有，未提前占有部分 gate，不改变容量、H2D 服务或 RDMA 速度。它重新使用 FIFO prefill，而不是为了保留 LLF 强行增加复杂性。
7. **不可抢占。** reservation-01 虽然完整回放结束，但定向反例显示其预测让已经启动的 3 秒 P 操作推迟到 3.1 秒结束，违反不可抢占契约。因此该版不入有效比较表。02 只对未获取资源的操作保留顺位，已获取 device gates、等待 link 的事务也必须继续完成。修复有失败前/通过后的定向证据，使用独立新目录重跑。

## 本轮选择与剩余问题

不将任何新候选称为三档稳定赢家。保留统一资源仲裁、已验证快照复用的 FairMemo 作为下一次比较参考，保留各部分成功版本；age 和 reservation-02 不升级，laxity 保留为实验候选。没有按速率拼出一个胜者。
reservation-02 高档虽恢复了更多前缀，restore 总时间 74.74→102.61 秒，compute 总时间 863.44→845.78 秒，规划/边界 wall 103.63→133.00 秒。候选最慢请求 git-multibranch:11 在 D API 内有 10.71 秒其他请求 compute，自己所在迭代 11.52 秒。更多缓存未转化为更低尾延迟。分量存在跨节点重叠，不可直接相加。
该请求在参考/候选上的常规 TTFT 为 26.36/33.17 秒，nominal 延迟却是 303.59/301.55 秒；因为候选的同会话上一轮更早结束，ready 提前，依赖等待更少。两种口径各自保留，不能靠切换指标制造收益。
下一步需要针对模型缺口，而非再加恢复惩罚：把当前 aggregate prefill 中的同步保存和逐 chunk 注意力成本分开校准；检查 queued requests 在未来发布/逐出后实际前缀与预测的偏差；验证 host-copy 整段占用源 device gate 是否为必要实现契约。当前只有 CPU，缺少新的并行 kernel、PCIe/NUMA 并发阶段测量，不能把这些系数识别成真实硬件带宽。

## 证据的边界

当前 95 请求、8 个完整自然会话已用于开发，三个到达流同 seed；actual causal ready 仍内生。D cap4、2GiB KV/host、128 token budget，shared-compute fraction=0。世界与预测共享粗粒度 singleton 成本；“compute”包含同步 prefill 保存，H2D task 不是纯 DMA。没有 PCIe/NUMA 并发微基准或新 batch kernel 标定，不能证明模拟已经贴合实机。CPU wall 被计入虚拟时间，也会导致不同执行间交错变化。

## 拒绝和保留

聚合 D 服务下界剪枝出现一次 bound > full forecast（7.1314 > 6.9804 秒），版本拒绝，部分结果不入表。其他回放通过不能抹掉失败。边界差异的最小状态仍未保存到可独立重放的 fixture，后续不得启用该剪枝。
源05 parent、memo、age、laxity 和 fair 的完整结果与哈希独立保留。age 不作为升级；fair 结果按报告结论选择参考或候选，不按速率拼接一个“胜者”。下一次实机应先检验 host-only copy 的 source device gate 必要性、完整 decode/同步发布及并行成本；不能把一个原型锁缺陷包装成普遍研究问题。
