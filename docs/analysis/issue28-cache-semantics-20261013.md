2026-10-13，在 zsx-91 双卡 Ascend 910B2 节点补充 decode 边界探针、
独立 FP64 递推和分块计算重放，并复核此前跨节点装载的完整输入身份。
**已观察到的两条输出分叉路径按后端浮点计算差异归档；本轮检查未发现前缀、
恢复边界或状态复制的语义错误。** 结论适用于已固定的 Qwen3.5 TP=2、BF16、
eager、同步调度、APC/align 配置和归档用例。

严格输出 token IDs 检查仍有差异。数值误差经过模型传播后可以改变生成文本，
本轮没有评估任务准确率，因此不能推导为模型质量不受影响。
适配验收采用完整状态恢复、正确输入身份、共同恢复边界及真实跳过 prefill 的口径，
保留原始严格输出结果作为已知数值限制。

## decode 路径的补充证据

沿用[原生 APC 诊断](issue28-native-apc-diagnosis-20261013.md)的固定模型、版本、
输入 IDs 和采样设置。使用原始模型计算路径、原生 vLLM/APC。完成四次模型请求：
目标输入冷计算两次、生产请求一次、保留生产缓存后的目标输入一次。

生产输入为 2047 tokens，生成的第一个 token 为 2586，恰好等于目标 2049-token
输入的第 2048 个 token。复用请求实际命中 2048 tokens；两个冷请求输出相同，
复用输出仍从第 4 个生成 token 分叉。

align 调度使冷请求先执行 2048-token prefill，再继续处理余下 1 token。
因此，本轮算子对照是**同一前缀的一次 2048-token prefill**与
**2047-token prefill 加 1-token decode**。

- 两个 TP rank 的第一层 QKV、a、b，在前 2047 个位置和第 2048 个位置均逐位一致。
- 第 2048 个 token 的 conv 输出、归一化 Q/K、V、g、beta 均逐位一致。
- 独立调用原生算子，逐位还原两个 rank 的生产 prefill 状态、decode 状态和 decode 输出。
- 30 个 GDN 层、两个 rank、conv/SSM 两种状态，共 **120/120 份**生产 checkpoint
  与复用请求进入第一步计算前的状态逐位一致。

这些结果排除了该路径中的输入 token 错配和 checkpoint 复制损坏。

## 独立数学递推与低精度计算

独立 CPU FP64 实现按以下公式逐 token 更新，状态布局为 `[value_dim, key_dim]`：

```text
S = exp(g) * S
delta = beta * (v - S @ k)
S = S + outer(delta, k)
o = S @ (q / sqrt(key_dim))
```

输入直接使用捕获的同一组归一化 Q/K、V、g、beta。
另实现 FP64 的 64-token 分块三角求解形式，核对其与逐 token 递推的数学等价性。

| 检查 | TP rank 0 | TP rank 1 |
| --- | ---: | ---: |
| decode 单步状态相对 FP64、同一初始状态：最大绝对差 | 1.76e-6 | 2.85e-6 |
| 同上：相对 RMS 差 | 3.81e-8 | 4.05e-8 |
| decode 输出与 FP64 输出转 BF16 | 逐位一致 | 逐位一致 |
| FP64 分块与 FP64 递推最终状态：最大绝对差 | 1.42e-13 | 1.28e-13 |
| 原生 prefill 与 FP64 递推状态：相对 RMS 差 | 0.458% | 0.436% |
| 原生 prefill 与 CPU BF16 状态过程模拟：相对 RMS 差 | 0.00662% | 0.00129% |

固定版本的 prefill 路径把三角解、W/U、块间 H 和衰减后的 delta 转为 BF16，
最终状态虽为 FP32，块间精度损失已经发生。decode 路径则对同一 FP32 状态做单步
更新。本轮记录实际 W/U 与门控累积值，在 CPU 中模拟 BF16 块间舍入、FP32 累加，
可解释原生 prefill 相对 FP64 差异的主要部分；余差保留为算子归约与舍入差异。

结合此前独立矩阵乘法重放和投影形状反事实，现有证据支持将两条诊断路径分别归为：
投影批次形状造成的低精度数值差异，以及分块 prefill 与单步 decode 的数值路径差异。
模型级对照使用原始计算路径，完整输出序列和差异均保留。

## 不同生产历史的缓存身份

重新核对[跨节点证据](issue28-qwen35-hybrid-cache-evidence-20261013/)中的
**3160 项装载记录、18 个目标请求**。除已有 checksum、物理 TP rank 和层的核对，
本轮还逐项关联原始保存日志中的边界、发布请求的输入 IDs 与消费请求的输入 IDs。

- 所有可匹配发布记录，在对应的 2048 或 4096 边界前，完整输入前缀与消费请求相同。
- 所有发布边界均位于该发布请求的 prompt 内；未使用生成后的状态冒充另一条 prompt。
- 前缀分叉用例的装载也对应自己的完整输入前缀；本轮没有发现错 key、错边界或错前缀。
- attention 与 recurrent 可来自不同生产请求，但在数学上对应相同因果前缀。
  在接受后端数值路径差异的口径下，生产请求 ID 不同本身不构成状态语义错误。

在本轮已核对的输入与边界范围内，跨组生产请求不同与恢复语义相容。
不同计算历史仍可能形成不同低精度状态和输出，实验应记录命中边界及
缓存来源条件。6144 边界不可用时恢复到 4096 并续算余下输入，是较短命中；
其 checkpoint 可用性留作命中率与性能观察事项。
