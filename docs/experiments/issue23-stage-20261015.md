# Issue #23：混合缓存现象实验阶段交付

本阶段交付完整混合缓存的 RDMA/本地拷贝 × 集中/平滑四组实验工具、推理运行效率修正、遥测与已执行结果。到达方式用于构造现象对照。研究重点是共享资源竞争、缓存完成尾延迟及其对推理的影响。

## 当前证据

| 记录 | 条件和用途 |
|---|---|
| [缓存路径基线](issue23-cache-path-performance-20261013.md) | 冷计算、本地复用、远端复用，记录完整恢复和回退；作为缓存路径诊断 |
| [首轮四组](issue23-hybrid-four-arm-results-20261014.md) | 完整混合缓存四组的首轮运行与分段分析 |
| [八请求测量](issue23-eight-request-results-20261014.md) | 1 Gb/s 共享软件注入额度；用户要求停止时保留 28 个完整配对批次，每组 224 条 |
| [推理运行配置](issue23-inference-runtime-20261015.md) | 图执行与异步调度的同节点对照及 P/D 资格检查 |
| [十六请求竞争实验](issue23-contention-pilot-20261015.md) | 原速 RDMA 与独立持续饱和 READ 背景；8 个完整配对批次，每组 128 条 |

这些运行的模型执行方式、批次与网络处理条件不同，绝对延迟不直接合并。最新测量使用图执行和异步调度，主测试用时 9 分 31 秒；校准与模型加载单独记录。

最新 RDMA 集中/平滑的缓存完成 p99 分别为 1953.88/131.29 毫秒。原生 QP batch 平均排队为 894.87/0.111 毫秒，而出队到完成约 119 毫秒。端点排队与到达集中程度的关系得到直接遥测支持。

RDMA 平均 TTFT 的集中减平滑差值为 1.747 秒，本地拷贝也有 1.368 秒。二者差分受首批高值影响，CPU 配额竞争也影响已有解码。因此，网络对 TTFT 和严格 TPOT 的独立效应仍需进一步隔离。Issue #23 保持开放。

## 工具入口

- `prepare_scaled.py` 固定不同输入和 cohort 身份；请求数必须能组成完整批次。
- `scaled_campaign.py` 运行常驻 P/D 服务上的配对批次，支持 2～16 条、间隔、前景注入额度、独立背景和预算。默认调度按显式环境变量启用，实际提交时序记录在 native trace 中。
- `rdma_background.py` 包装 perftest 的持续 RC READ，周期记录实际吞吐；`expected_gbps` 为校准参考。该工具模式不保证固定比例份额。
- `resource_telemetry.py`、连接器遥测与 `telemetry_worker.py` 记录资源、缓存恢复与模型工作。分析区分 SSE 消息间隔、模型工作事件和传输队列统计对象。
- `verify_contention.py` 从公开证据子集重算报告；`render_contention.py` 生成图片。

部署参数由既有 `deployment_runtime.py`、`lifecycle.py` 和 `node_agent.py` 提供。部署配置必须填入实际共享根目录、模型 revision、Python/native runtime 路径、两节点地址、端口和私有控制 token 路径。节点代理绑定配置地址，控制请求使用私有 token。实验 HTTP 接口仅用于已显式启用 Issue23 的 engine；源快照与 epoch 切换必须在对应引用/传输完成后执行。

最新冻结参数位于 [测量 contract](../../results/issue23/20261015-contention/pilot-analysis.json)，示例测量调用为：

```bash
python scripts/issue23/scaled_campaign.py --config /path/to/two-node.json \
  --label new-pilot --limit 8 --rate 0 --interval 144 --period 8 \
  --baseline-seconds 1 --recovery-seconds 1
```

上述 144 毫秒来自本轮校准，换环境后须按实测容量与竞争下服务时间重新冻结。复用已有 source capture 和隐藏镜像，四组均保留同一输入、完整对象与平均释放偏移；前景仍含 P 端冷 prefill。

## 验证与运行版本

512 次实际前景执行全部完成完整载荷，两 TP rank 共 1024 条首次工作记录均为 `computed_tokens=4096`、`scheduled_tokens=1`。[公开证据与复核命令](../../results/issue23/20261015-contention/README.md) 保存可迁移的输入、native 事件、客户端数据和遥测投影，CI 自动复核。

合并整理中的自审修正包括：源快照控制要求实验显式启用；pacing rate 切换与 batch 入队计数使用同一锁保护；严格实时模式在其专用线程释放；清理一端失败后仍尝试另一端；可选原生背景调用的参数顺序与传输 API 对齐。默认优先级的 cohort 释放路径继续采用本轮已测路径。运行记录保存启动目录源码快照及原生制品身份：Python overlay 使用此目录，原生制品复用此前构建，归档未建立其与整份快照的逐文件构建对应关系。后续修正的验收单独记录。

默认 Python 回归、实验工具回归、Rust 格式与双特性编译检查，以及冻结证据复核构成代码验收。模型 E2E 是仓库的合并前检查，最终提交的硬件验收范围随 PR 一并登记。
