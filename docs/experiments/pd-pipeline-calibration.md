# Iteration-aware P/D simulation

`scripts/issue23/pd_pipeline_simulator.py` models scheduler-visible cache
discovery, asynchronous prefetch, copy cohorts, a FIFO native copy worker and
completion feedback at engine iteration boundaries. It accepts the same workload
and deployment configuration as `pd_multinode_simulator.py`.

The workload contains token lengths, chained prefix identities, offered arrival
times, output budgets, dependencies and routes. Request latency is generated by
the simulator. Physical CPU, NIC, NPU KV and host-cache capacities are shared by
the engines assigned to each host.

## Calibration

`fit_pipeline_profile.py` accepts normalized calibration evidence and a reference
profile. Conditions have equal total fit weight, so a long decode sequence does
not dominate merely by producing more observed iterations. Fits use nonnegative
coefficients and robust residual weighting.

The decoder candidates use either total context and sequence count, or graph
batch padding, total context and maximum context. Selection leaves out whole
role-swapped acquisition phases and context bands. The graph model must improve
grouped error by more than 5% to replace the smaller model. Copy/compute slowdown
is selected from a small fixed family using role-swapped calibration phases.
Request identity, session identity, machine identity and offered rate do not
appear in service-cost features.

The copy candidates also compare a shared per-block cost with a resource model
using measured destination copy capability (`host_copy_GBps`). Two isolated
128-block probes supply that input; those probes are excluded from coefficient
fitting and validation scores. Cross-host scores for this candidate are
conditional on a fresh component probe of the destination. They do not establish
hardware transfer without calibration. Native restoration capability describes
the measured backend path and its current state, rather than the physical PCIe
link rate. Backend state changes can invalidate an earlier probe.

The acquired copy telemetry reports the total blocks of a cohort. Attribute its
payload once, across the associated requests; copying the cohort block count to
every request would multiply the measured transfer volume incorrectly.

## Independent evaluation

Freeze the selected profile and simulator before opening heldout latency
outcomes. Compare the previous frozen simulator, the legacy architecture refitted
on the same calibration data, and the iteration-aware architecture. Report
request-wise TTFT and E2E errors, signed bias, percentile errors and P/D stage
errors separately. Small end-to-end bias can conceal opposing stage biases.

Keep complete sessions together during validation. Multiple rates over the same
sessions are repeated measurements, rather than independent workload samples.
Record actual arrivals, dependencies, routing, observed cache reuse and engine
capacities so differences in executed work can be distinguished from cost error.

## Application range

The current acquisition targets Qwen2.5-7B-Instruct BF16, TP1, graph execution on
Ascend 910B2. Training covers role swaps across two physical hosts, variable
context lengths, mixed arrivals, copy/decode overlap and bounded fan-in. Heldout
workloads and a heldout token-budget/concurrency configuration test whether the
costs transfer beyond their fitted conditions.

P/D counts, routing, arrival processes, output budgets and cache capacities are
scenario inputs. Larger counts still depend on the accuracy of the shared-host
resource model. A new model, accelerator, execution backend or topology needs an
appropriate component profile. Simulations outside observed compute features or
copy cohort ranges are marked as extrapolations. NPU memory preemption currently
raises an explicit capacity error because its service costs are uncalibrated.
Network service is an aggregate endpoint resource; switch queues, packets, ECN
and PFC require separate network evidence.

Retain a profile's independent validation report alongside its coefficients.
Improved component fits alone do not qualify whole-request TTFT predictions.
The October 27 acquisition found strong decoder-step agreement but substantial
native copy variability and a failed new-session TTFT condition. The pipeline
profile therefore remains conditionally qualified for scenario exploration;
whole-request tail accuracy needs further backend profiling and fresh validation.
