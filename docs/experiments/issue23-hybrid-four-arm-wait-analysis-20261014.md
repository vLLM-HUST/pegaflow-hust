# 四组实验的等待扣除与延迟定位

使用 2026 年 10 月 14 日首轮的 32 条测量请求和原始遥测，逐请求重新计算。
本次分析使用已保存的数据。

## 人工等待的定义

令 `t_eligible_i` 为请求 i 的完整混合缓存 bundle 已准备好传输的时刻，
`Tg` 为同一 cohort 四条请求中最晚的 `t_eligible`。

```
人工等齐等待_i = Tg - t_eligible_i
扣除后 TTFT_i = 原始 TTFT_i - 人工等齐等待_i
```

该等待来自实验设置的四请求同步门控。它保证集中和平滑的比较都从同一
“四条请求已可传输”的条件开始；应与业务处理时间分开报告。
这里保留了集中组 15 ms、平滑组 0/10/20/30 ms 的提交偏移，因为它们就是
实验处理本身。各请求先扣除各自的等待，然后重新统计分布。

`prefill 完成 → bundle eligible` 还包含缓存可见性、D 端查询、分组组装和
描述符准备。这些环节有实际用途。计算中采用同一个 D 端 engine 的单调
时钟，避免用两台机器的 wall clock 精确相减。

## 扣除结果

单位为秒，每组 8 条请求。

| 传输 / 提交方式 | 原始 TTFT 均值 | 人工等待均值 | 扣除后 TTFT 均值 | 扣除后 p50 |
|---|---:|---:|---:|---:|
| RDMA / 集中 | 3.217 | 0.526 | 2.692 | 2.868 |
| RDMA / 平滑 | 3.454 | 0.586 | 2.868 | 3.035 |
| 本地拷贝 / 集中 | 3.289 | 0.558 | 2.732 | 2.762 |
| 本地拷贝 / 平滑 | 4.597 | 0.550 | 4.048 | 3.949 |

扣除后，本轮集中组均值仍较低。人工等待解释了整体约半秒的开销，但不能
解释本地拷贝两组之间约 1.3 秒的均值差。该集中组仍保留原有的一个 cohort
提交跨度 1.983 ms、超过 1 ms 阈值的时序资格标记。

这是对已经发生的执行进行耗时分解。实际取消门控会改变传输与计算的重叠、
模型批次和资源竞争，因此扣除值应作为诊断指标，不能代替重新运行得到的
客户端 TTFT。

## 反向结果的主要证据

网络/CPU 缓存获取之后，还有 host→NPU 恢复、load 完成通知、模型批处理和
首 token 返回。当前最大的异常已定位在缓存获取完成后的恢复阶段。

| FrontierScience cohort | 传输完成到首个模型计算的平均间隔 | 两个 TP rank 中较慢的 native host→NPU load task |
|---|---:|---:|
| RDMA / 集中 | 0.379 s | 0.098 s |
| RDMA / 平滑 | 0.841 s | 0.509 s |
| 本地拷贝 / 集中 | 0.611 s | 0.207 s |
| 本地拷贝 / 平滑 | 3.139 s | 2.906 s |

native load task 的计时包括描述符构建、H2D 调用和 stream 同步；不能直接
解释为纯 DMA 的执行时间。第一批 MMLU 请求当时仍在连续解码，日志显示
第二批 FrontierScience 请求与它们的计算负载重叠。

本地拷贝平滑组中，FrontierScience 第一条请求以自身 bundle 完成为零点：

| 事件 | 相对时间 |
|---|---:|
| worker 开始恢复到设备 | +0.166 s |
| worker 观察到恢复完成 | +3.126 s |
| 第一次进入该请求的模型计算 | +3.151 s |
| 第一次 execute_model 返回 | +3.502 s |

该组四条请求的实际 CPU 拷贝仅为 29–35 ms。native 日志中，逻辑 device 0
的恢复耗时为 2905.56 ms，device 1 为 498.53 ms。相同 cohort 在本地拷贝
集中组对应为 207.04 ms、156.19 ms。因此，本轮较高 TTFT 主要伴随着恢复到
NPU 的长延迟，不能归因于那次几十毫秒的 CPU 拷贝。

还观察到不同的模型批次：本地拷贝集中组的 MMLU 四条请求同时进入首个
计算步骤，平滑组先进入一条、其余三条进入下一步骤。约 10 ms 的提交间隔
可以改变请求落在哪个约 0.3–0.4 s 的模型步骤中。批处理变化是需要纳入
端到端分析的机制。

当前已定位延迟阶段。已有解码负载与恢复操作的资源/stream 竞争是主要
候选原因；具体在 H2D 提交、同步还是其他运行时环节，还需进一步拆解。
一轮、固定组顺序和每组八条请求，也限制了对稳定效应的推断。

下一轮优先控制 cohort 重叠，并分别记录获取、H2D 提交/完成、同步和模型
准入。客户端 TTFT、人工门控等待和 gate 后首 token 延迟应同时报告。
